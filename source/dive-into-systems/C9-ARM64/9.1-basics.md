*9.1. Diving into Assembly: Basics*

为了初步了解汇编，我们修改[汇编入门章节](../C6-asm_intro/6.0-index.html)中的 `adder` 函数，简化它的行为。修改后的函数（`adder2`）如下：

> For a first look at assembly, we modify the `adder` function from the [assembly introduction chapter](../C6-asm_intro/6.0-index.html) to simplify its behavior. The modified function (`adder2`) is shown here:

```
#include <stdio.h>

//adds two to an integer and returns the result
int adder2(int a) {
    return a + 2;
}

int main(void) {
    int x = 40;
    x = adder2(x);
    printf("x is: %d\n", x);
    return 0;
}
```

要编译这段代码，使用以下命令：

> To compile this code, use the following command:

```
$ gcc -o adder adder.c
```

接下来，用 `objdump` 命令查看这段代码对应的汇编：

> Next, let’s view the corresponding assembly of this code by using the `objdump` command:

```
$ objdump -d adder > output
$ less output
```

用 `less` 查看文件 `output` 时，输入 `/adder` 搜索与 `adder2` 相关的代码片段。与 `adder` 相关的部分应该类似下面这样：

> Search for the code snippet associated with `adder2` by typing `/adder` while examining the file `output` using `less`. The section associated with `adder` should look similar to the following:

*`adder2` 函数的汇编输出*

> *Assembly output for the `adder2` function*

```
0000000000000724 <adder2>:
 724:   d10043ff        sub     sp, sp, #0x10
 728:   b9000fe0        str     w0, [sp, #12]
 72c:   b9400fe0        ldr     w0, [sp, #12]
 730:   11000800        add     w0, w0, #0x2
 734:   910043ff        add     sp, sp, #0x10
 738:   d65f03c0        ret
```

如果你还不明白这是怎么回事，不必担心。我们会在后面的小节中更详细地介绍汇编。目前，我们先来研究一下这些单独指令的结构。

> Don’t worry if you don’t understand what’s going on just yet. We will cover assembly in greater detail in future sections. For now, let’s study the structure of these individual instructions.

上例中的每一行都包含一条指令在程序内存中的 64 位地址（为节省空间，只保留最低三位数字）、与这条指令对应的字节，以及指令本身的文本表示。例如，`d10043ff` 是指令 `sub sp, sp, #0x10` 的机器码表示，这条指令位于代码段内存中的地址 `0x724` 处。注意，`0x724` 是与 `sub sp, sp #0x10` 指令相关的完整 64 位地址的缩写；为了便于阅读，`objdump` 省略了前导零。

> Each line in the preceding example contains the instruction’s 64-bit address in program memory (shortened to the lowest three digits to save space), the bytes corresponding to the instruction, and the plain-text representation of the instruction itself. For example, `d10043ff` is the machine code representation of the instruction `sub sp, sp, #0x10`, and the instruction occurs at address `0x724` in code memory. Note that `0x724` is an abbreviation of the full 64-bit address associated with the `sub sp, sp #0x10` instruction; `objdump` omits the leading zeros to help with readability.

> [!NOTE] 译注
> A64 的每条指令都固定为 4 字节，所以清单中的地址每行恰好加 4（0x724、0x728、0x72c……），这与 x86 的变长指令形成鲜明对比。

要注意，一行 C 代码常常会被翻译成多条汇编指令。运算 `a + 2` 由代码段内存地址 `0x728` 到 `0x730` 处的三条指令表示：`str w0, [sp, #12]`、`ldr w0, [sp, #12]` 和 `add w0, w0, #0x2`。

> It is important to note that a single line of C code often translates to multiple instructions in assembly. The operation `a + 2` is represented by the three instructions at code memory addresses `0x728` through `0x730`: `str w0, [sp, #12]`, `ldr w0, [sp, #12]`, and `add w0, w0, #0x2`.

>

Most of the assembly examples in this chapter were generated on a Raspberry Pi 3B+ running the 64-bit Ubuntu Mate operating system and using GCC. If you use a different operating system, a different compiler, or a different Raspberry Pi or single-board computer, your assembly output may vary.
> >

Consequently, there are many seemingly redundant instructions in the examples that follow. During this translation process, it is not uncommon for some redundancy to occur. Optimizing compilers remove many of these redundancies during optimization, which is covered in a [later chapter](../C12-CodeOpt/12.0-index.html).

### 9.1.1. 寄存器

*9.1.1. Registers*

回想一下，**寄存器**是直接位于 CPU 上的、字大小的存储单元。ARMv8 CPU 共有 31 个用于存储 64 位通用数据的寄存器：`x0` 到 `x30`。尽管程序可能会把寄存器的内容解释为整数或地址，但寄存器本身并不加以区分。程序可以读写全部 31 个寄存器。

> Recall that a **register** is a word-sized storage unit located directly on the CPU. The ARMv8 CPU has a total of 31 registers for storing general-purpose 64-bit data: `x0` to `x30`. Whereas a program may interpret a register’s contents as integers or as addresses, the register itself makes no distinction. Programs can read from or write to all 31 registers.

ARMv8-A ISA 还规定了一些专用寄存器。首先值得注意的两个是**栈指针**寄存器（`sp`）和**程序计数器**寄存器（`pc`）。编译器把 `sp` 寄存器保留给维护程序栈布局的操作。`pc` 寄存器指向 CPU 要执行的下一条指令；与其他寄存器不同，程序不能直接写 `pc` 寄存器。其次，**零寄存器** `zr` 永远存放值 0，只在作为源寄存器时有用。

> The ARMv8-A ISA also specifies special-purpose registers. The first two worth noting are the **stack pointer** register (`sp`) and the **program counter** register (`pc`). The compiler reserves the `sp` register for maintaining the layout of the program stack. The `pc` register points to the next instruction to be executed by the CPU; unlike the other registers, programs cannot write directly to the `pc` register. Next, the **zero register** `zr` permanently stores the value 0, and is only useful as a source register.

> [!NOTE] 译注 · 零寄存器
> 在汇编中零寄存器写作 `xzr`（64 位）或 `wzr`（32 位）。它也可以出现在目标位置，写入的结果会被直接丢弃：例如比较指令 `cmp x0, x1` 实际上就是 `subs xzr, x0, x1`（只要标志位、扔掉差值）。译者用 Clang 汇编这两条指令，得到的机器码完全相同（`eb01001f`）。

### 9.1.2. 寄存器的进阶记法

*9.1.2. Advanced Register Notation*

由于 ARMv8-A 是 32 位 ARMv7-A 体系结构的扩展，A64 ISA 提供了访问每个通用寄存器低 32 位的机制，即 `w0` 到 `w30`。[图 1](9.1-basics.html) 展示了寄存器 `x0` 的一个示例布局。如果把 32 位数据存到组成部分寄存器 `w0` 中，寄存器的高 32 位就无法访问，并且会被清零。

> Since ARMv8-A is an extension of the 32-bit ARMv7-A architecture, the A64 ISA provides mechanisms to access the lower 32 bits of each of the general-purpose registers, or `w0` through `w30`. [Figure 1](9.1-basics.html) shows a sample layout of register `x0`. If 32-bit data is stored in component register `w0`, then the upper 32 bits of the register become inaccessible, and are zeroed out.

![32-bit component register w0 and its relation to the 64-bit x0 register](/dive-into-systems/C9-ARM64/images/register.png)

**图 1.** 寄存器 %x0 的组成部分寄存器布局

*Figure 1. Component register layout of register %x0.*

> [!WARNING] 原书警示 · 编译器可能会根据类型选用寄存器的组成部分（The compiler may choose component registers depending on type）
> 阅读汇编代码时要记住，编译器在处理 64 位值（例如指针或 `long` 类型）时通常使用 64 位寄存器，在处理 32 位类型（例如 `int`）时则使用 32 位的组成部分寄存器。在 A64 中，32 位的组成部分寄存器与完整的 64 位寄存器混合使用是非常常见的。例如，在前面的 `adder2` 函数中，编译器引用的是组成部分寄存器 `w0` 而不是 `x0`，因为在 64 位系统上 `int` 类型通常占 32 位（四个字节）。如果 `adder2` 函数的参数是 `long` 而不是 `int`，编译器就会把 `a` 存放在寄存器 `x0` 而不是组成部分寄存器 `w0` 中。
>
> > When reading assembly code, keep in mind that the compiler typically uses the 64-bit registers when dealing with 64-bit values (e.g., pointers or `long` types) and the 32-bit component registers when dealing with 32-bit types (e.g., `int`). In A64, it is very common to see 32-bit component registers intermixed with the full 64-bit registers. For example, in the `adder2` function shown earlier, the compiler references component register `w0` instead of `x0` given that `int` types typically take up 32 bits (four bytes) of space on 64-bit systems. If the `adder2` function had a `long` parameter instead of an `int` parameter, the compiler would store `a` in register `x0` instead of component register `w0`.

对于之前熟悉 A32 ISA 的读者，需要注意 A32 ISA 中的 32 位通用寄存器 `r0` 到 `r12` 映射到 A64 的组成部分寄存器 `w0` 到 `w12`。A64 ISA 可用的寄存器数量是原来的两倍多。

> For readers previously familiar with the A32 ISA, it is important to note that the 32-bit general-purpose registers `r0` to `r12` from the A32 ISA map to the A64 component registers `w0` to `w12`. The A64 ISA more than doubles the number of available registers.

### 9.1.3. 指令的结构

*9.1.3. Instruction Structure*

每条指令由一个指明它做什么的操作码（**opcode**）和一个或多个告诉指令如何去做的**操作数**（operand）组成。大多数 A64 指令通常采用下面的格式：

> Each instruction consists of an operation code (or **opcode**) that specifies what it does, and one or more **operands** that tells the instruction how to do it. For most A64 instructions, the following format is typically used:

```
opcode D, O1, O2
```

其中 `opcode` 是操作码，`D` 是目标寄存器，`O1` 是第一个操作数，`O2` 是第二个操作数。例如，指令 `add w0, w0, #0x2` 的操作码是 `add`，目标寄存器是 `w0`，两个操作数是 `w0` 和 `#0x2`。操作数有多种类型：

> Where `opcode` is the operation code, `D` is the destination register, `O1` is the first operand, and `O2` the second operand. For example, the instruction `add w0, w0, #0x2` has the opcode `add`, a destination register of `w0`, and the two operands `w0` and `#0x2`. There are multiple types of operands:

> [!NOTE] 译注
> 注意 ARM 汇编的目标在*前*（`add D, O1, O2`），与第 7、8 章 x86 的 AT&T 语法（目标在后）正好相反。

- **常数（字面量）**值前面带有 `#` 符号。例如，在指令 `add w0, w0, #0x2` 中，操作数 `#0x2` 是一个字面值，对应于十六进制值 0x2。

> - **Constant (literal)** values are preceded by the `#` sign. For example, in the instruction `add w0, w0, #0x2`, the operand `#0x2` is a literal value that corresponds to the hexadecimal value 0x2.

- **寄存器**形式指单个寄存器。指令 `add sp, sp, #0x10` 用栈指针寄存器 `sp` 来指定目标寄存器，以及 `add` 指令所需两个操作数中的第一个。

> - **Register** forms refer to individual registers. The instruction `add sp, sp, #0x10` uses the stack pointer register `sp` to designate the destination register and the first of the two operands needed for the `add` instruction.

- **内存**形式对应于主存（RAM）中的某个值，常用于地址查找。内存地址形式可以包含寄存器和常数值的组合。例如，在指令 `str w0, [sp, #12]` 中，操作数 `[sp, #12]` 就是内存形式的一个例子。它大致可以翻译为：「把 12 加到寄存器 `sp` 中的值上，然后对得到的地址执行一次内存查找」。如果这听起来像是指针解引用，那是因为它就是！

> - **Memory** forms correspond to some value inside main memory (RAM) and are commonly used for address lookups. Memory address forms can contain a combination of registers and constant values. For example, in the instruction `str w0, [sp, #12]`, the operand `[sp, #12]` is an example of a memory form. It loosely translates to "add 12 to the value in register `sp`, and then perform a memory lookup on the corresponding address." If this sounds like a pointer dereference, that’s because it is!

### 9.1.4. 一个关于操作数的例子

*9.1.4. An Example with Operands*

详细解释操作数的最好方式是举一个简短的例子。假设内存中包含以下值：

> The best way to explain operands in detail is to present a quick example. Suppose that memory contains the following values:

| 地址 | 值 |
|---------|-------|
| 0x804 | 0xCA |
| 0x808 | 0xFD |
| 0x80c | 0x12 |
| 0x810 | 0x1E |

> | Address | Value |
> |---------|-------|
> | 0x804   | 0xCA  |
> | 0x808   | 0xFD  |
> | 0x80c   | 0x12  |
> | 0x810   | 0x1E  |

我们再假设下面这些寄存器中存放着所示的值：

> Let’s also assume that the following registers contain the values:

| 寄存器 | 值 |
|---|---|
| `x0` | 0x804 |
| `x1` | 0xC |
| `x2` | 0x2 |
| `w3` | 0x4 |

> | Register | Value |
> |----------|-------|
> | `x0`     | 0x804 |
> | `x1`     | 0xC   |
> | `x2`     | 0x2   |
> | `w3`     | 0x4   |

那么，[表 1](9.1-basics.html) 中的操作数会求值为表中所示的值。表中的每一行把一个操作数与它的形式（例如常数、寄存器、内存）、它的含义以及它的值对应起来。

> Then the operands in [Table 1](9.1-basics.html) evaluate to the values shown there. Each row of the table matches an operand with its form (e.g., constant, register, memory), how it is translated, and its value.

**表 1.** 操作数示例

*Table 1. Example Operands*

| 操作数 | 形式 | 含义 | 值 |
|----|----|----|----|
| `x0` | 寄存器 | `x0` | 0x804 |
| `[x0]` | 内存 | \*(0x804) | 0xCA |
| `#0x804` | 常数 | 0x804 | 0x804 |
| `[x0, #8]` | 内存 | \*(`x0` + 8) 即 \*(0x80c) | 0x12 |
| `[x0, x1]` | 内存 | \*(`x0` + `x1`) 即 \*(0x810) | 0x1E |
| `[x0, w3, SXTW]` | （符号扩展）内存 | \*(`x0` + SignExtend(`w3`)) 即 \*(0x808) | 0xFD |
| `[x0, x2, LSL, #2]` | 带比例的内存 | \*(`x0` + (`x2 << 2`)) 即 \*(0x80c) | 0x12 |
| `[x0, w3, SXTW, #1]` | （符号扩展）带比例的内存 | \*(`x0` + SignExtend(`w3 << 1`)) 即 \*(0x80c) | 0x12 |

> | Operand | Form | Translation | Value |
> |----|----|----|----|
> | `x0` | Register | `x0` | 0x804 |
> | `[x0]` | Memory | \*(0x804) | 0xCA |
> | `#0x804` | Constant | 0x804 | 0x804 |
> | `[x0, #8]` | Memory | \*(`x0` + 8) or \*(0x80c) | 0x12 |
> | `[x0, x1]` | Memory | \*(`x0` + `x1`) or \*(0x810) | 0x1E |
> | `[x0, w3, SXTW]` | (Sign-Extend) Memory | \*(`x0` + SignExtend(`w3`)) or \*(0x808) | 0xFD |
> | `[x0, x2, LSL, #2]` | Scaled Memory | \*(`x0` + (`x2 << 2`)) or \*(0x80c) | 0x12 |
> | `[x0, w3, SXTW, #1]` | (Sign-Extend) Scaled Memory | \*(`x0` + SignExtend(`w3 << 1`)) or \*(0x80c) | 0x12 |

> [!NOTE] 译注 · 表中两处写法
> - 实际汇编语法中移位说明符与移位量之间没有逗号：应写作 `[x0, x2, lsl #2]`、`[x0, w3, sxtw #1]`。译者用 Clang 汇编 `ldr w1, [x0, x2, lsl, #2]` 会报错，去掉逗号后通过。
> - 寄存器偏移的移位量不能随意选：它只能是 0 或「访问宽度的 log₂」。所以 `ldr w1, [x0, w3, sxtw #1]`（4 字节加载配 `#1`）会被汇编器拒绝，只有 2 字节加载 `ldrh w1, [x0, w3, sxtw #1]` 才合法；4 字节加载只能用 `#2`（或不移位）。表中按「`w3` 左移 1 位」算出的 0x80c 只是演示寻址计算。

在[表 1](9.1-basics.html) 中，记号 `x0` 表示 64 位寄存器 `x0` 中存放的值，而 `w3` 表示组成部分寄存器 `w3` 中存放的 32 位值。操作数 `[x0]` 表示应当把 `x0` 中的值当作一个地址，并对它解引用（查找该地址处的值）。因此，操作数 `[x0]` 对应于 \*(0x804)，即值 0xCA。可以用字的符号扩展（`SXTW`）指令把对 32 位寄存器的操作与 64 位寄存器结合起来。所以，`[x0, w3, SXTW]` 先把 `w3` 符号扩展为 64 位值，再把它加到 `x0` 上并执行内存查找。最后，带比例的内存类型可以通过左移来计算偏移量。

> In [Table 1](9.1-basics.html), the notation `x0` indicates the value stored in 64-bit register `x0`, whereas `w3` indicates a 32-bit value stored in component register `w3`. The operand `[x0]` indicates that the value inside `x0` should be treated as an address, and to dereference (look up) the value at that address. Therefore, the operand `[x0]` corresponds to \*(0x804) or the value 0xCA. An operation on a 32-bit register can be combined with a 64-bit register using the sign-extend word (`SXTW`) instruction. So, `[x0, w3, SXTW]` sign extends `w3` into a 64-bit value before adding it to `x0` and performing a memory lookup. Lastly, scaled memory types enable the calculation of offsets through the use of a left shift.

在继续之前，有几点重要说明。尽管[表 1](9.1-basics.html) 列出了许多合法的操作数形式，但并不是所有形式在所有情况下都可以互换使用。

> A few important notes before continuing. Although [Table 1](9.1-basics.html) shows many valid operand forms, not all forms can be used interchangeably in all circumstances.

具体来说：

> Specifically:

- 不能直接对内存中的数据进行读写运算；ARM 遵循加载/存储（load/store）模型，要求数据在寄存器中进行运算。因此，数据必须先被传送到寄存器才能参与运算，运算完成后再传送回内存。

> - Data cannot be read or written to memory directly; instead, ARM follows a load/store model, which requires data to be operated on in registers. Thus, data must be transferred to registers before being operated on, and transferred back to memory after the operations are complete.

- 指令的目标部分必须始终是寄存器。

> - The destination component of an instruction must always be a register.

[表 1](9.1-basics.html) 是供参考的；不过，理解关键的操作数形式会帮助读者更快地读懂汇编语言。

> [Table 1](9.1-basics.html) is provided as a reference; however, understanding key operand forms will help improve the reader’s speed in parsing assembly language.
