*9.9. structs in Assembly*

[结构体](../C2-C_depth/2.7-structs.html)是在 C 中创建数据类型集合的另一种方式。与数组不同，结构体可以把不同的数据类型组合在一起。C 像存放一维数组那样存放 `struct`，其数据元素（字段）连续存放。

> A [`struct`](../C2-C_depth/2.7-structs.html) is another way to create a collection of data types in C. Unlike arrays, they enable different data types to be grouped together. C stores a `struct` like a single-dimension array, where the data elements (fields) are stored contiguously.

我们再来看第 1 章中的 `struct studentT`：

> Let’s revisit `struct studentT` from Chapter 1:

```
struct studentT {
    char name[64];
    int  age;
    int  grad_yr;
    float gpa;
};

struct studentT student;
```

[图 1](9.9-structs.html) 展示了 `student` 在内存中的布局。每个 a<sub>i</sub> 表示内存中的一个偏移。

> [Figure 1](9.9-structs.html) shows how the `student` is laid out in memory. Each a<sub>i</sub> denotes an offset in memory.

![structArray](/dive-into-systems/C9-ARM64/images/structArray.png)

**图 1.** struct studentT 的内存布局

*Figure 1. The memory layout of a struct studentT.*

各字段按照声明的顺序在内存中一个挨一个地连续存放。在[图 1](9.9-structs.html) 中，`age` 字段被分配在紧跟 `name` 字段之后的内存位置（字节偏移 a<sub>64</sub>），后面依次是 `grad_yr`（字节偏移 a<sub>68</sub>）和 `gpa`（字节偏移 a<sub>72</sub>）字段。这种组织方式使访问字段既节省内存又高效。

> Each field is stored contiguously next to one another in memory in the order in which they are declared. In [Figure 1](9.9-structs.html), the `age` field is allocated at the memory location directly after the `name` field (at byte offset a<sub>64</sub>) and is followed by the `grad_yr` (byte offset a<sub>68</sub>) and `gpa` (byte offset a<sub>72</sub>) fields. This organization enables memory-efficient access to the fields.

为了理解编译器如何生成处理 `struct` 的汇编代码，考虑函数 `initStudent`：

> To understand how the compiler generates assembly code to work with a `struct`, consider the function `initStudent`:

```
void initStudent(struct studentT *s, char *nm, int ag, int gr, float g) {
    strncpy(s->name, nm, 64);
    s->grad_yr = gr;
    s->age = ag;
    s->gpa = g;
}
```

`initStudent` 函数以一个 `struct studentT` 的基地址作为第一个参数，以各字段想要设置的值作为其余参数。下面的清单给出了这个函数的汇编：

> The `initStudent` function uses the base address of a `struct studentT` as its first parameter, and the desired values for each field as its remaining parameters. The following listing depicts this function in assembly:

```

0x7f8 <+4>:  mov  x29, sp                // x29 = sp (frame ptr = stack ptr)
0x7fc <+8>:  str  x0, [x29, #40]         // store s at x29 + 40
0x800 <+12>: str  x1, [x29, #32]         // store nm at x29 + 32
0x804 <+16>: str  w2, [x29, #28]         // store ag at x29 + 28
0x808 <+20>: str  w3, [x29, #24]         // store gr at x29 + 24
0x80c <+24>: str  s0, [x29, #20]         // store g at x29 + 20
0x810 <+28>: ldr  x0, [x29, #40]         // x0 = s
0x814 <+32>: mov  x2, #0x40              // x2 = 0x40 (or 64)
0x814 <+36>: ldr  x1, [x29, #32]         // x1 = nm
```

留意每个字段的字节偏移，是理解这段代码的关键。下面是几点需要记住的事情。

> Being mindful of the byte offsets of each field is key to understanding this code. Here are a few things to keep in mind.

- `strncpy` 调用以 `s` 的 `name` 字段的基地址、数组 `nm` 的地址和一个长度说明作为它的三个实参。回想一下，由于 `name` 是 `struct studentT` 中的第一个字段，`s` 的地址与 `s→name` 的地址是同一个。

> - The `strncpy` call takes the base address of the `name` field of `s`, the address of array `nm`, and a length specifier as its three arguments. Recall that since `name` is the first field in `struct studentT`, the address of `s` is synonymous with the address of `s→name`.

> [!NOTE] 译注 · 清单中的几处笔误
> - 与第 7、8 章相同，原书网页把 `->` 排版成了箭头「→」，代码中要写作 `s->name`。
> - 上面完整清单第一行的注释「store x29, x30 at sp, sp+4」应为 `sp` 和 `sp+8`：`x29`、`x30` 都是 8 字节寄存器（最后一条 `ldp` 的注释同理）。
> - 清单从 `<+36>` 起地址与偏移对不上：`initStudent` 从 0x7f4 开始，`<+36>` 应在 0x818，清单却写成了重复的 0x814，此后各行的地址都差 4；末尾几行的偏移（`<+80>`、`<+84>`、`<+88>`）也跳了号。这应是手工编辑清单时造成的，不影响理解各条指令的作用。

```
0x7fc <+8>:  str  x0, [x29, #40]         // store s at x29 + 40
0x800 <+12>: str  x1, [x29, #32]         // store nm at x29 + 32
0x804 <+16>: str  w2, [x29, #28]         // store ag at x29 + 28
0x808 <+20>: str  w3, [x29, #24]         // store gr at x29 + 24
0x80c <+24>: str  s0, [x29, #20]         // store g at x29 + 20
0x810 <+28>: ldr  x0, [x29, #40]         // x0 = s
0x814 <+32>: mov  x2, #0x40              // x2 = 0x40 (or 64)
0x814 <+36>: ldr  x1, [x29, #32]         // x1 = nm
0x818 <+40>: bl   0x6e0 <strncpy@plt>    // call strncpy(s, nm, 64) (s->name)
```

- 上面的代码片段中有一个之前没有讨论过的寄存器（`s0`）。`s0` 寄存器是专门用于浮点值的寄存器的一个例子。

> - The above code snippet contains an undiscussed register (`s0`). The `s0` register is an example of a register reserved for floating point values.

> [!NOTE] 译注
> AArch64 有 32 个 128 位的浮点/SIMD 寄存器 `v0`–`v31`，按访问宽度写作 `s0`（32 位单精度）、`d0`（64 位双精度）等。浮点参数依次通过 `s0`/`d0`–`s7`/`d7` 传递，与整数参数的 `x0`–`x7` 各自独立编号，所以第五个参数 `g`（`float`）用的是第一个浮点寄存器 `s0`。

- 下一部分（指令 `<initStudent+44>` 到 `<initStudent+52>`）把参数 `gr` 的值放到距 `s` 起始处偏移 68 的位置。回顾一下[图 1](9.9-structs.html) 中结构体的内存布局可以看出，这个地址对应于 `s→grad_yr`。

> - The next part (instructions `<initStudent+44>` thru `<initStudent+52>`) places the value of the `gr` parameter at an offset of 68 from the start of `s`. Revisiting the memory layout of the struct in [Figure 1](9.9-structs.html) shows that this address corresponds to `s→grad_yr`.

```
0x81c <+44>: ldr  x0, [x29, #40]         // x0 = s
0x820 <+48>: ldr  w1, [x29, #24]         // w1 = gr
0x824 <+52>: str  w1, [x0, #68]          // store gr at (s + 68) (s->grad_yr)
```

- 下一部分（指令 `<initStudent+56>` 到 `<initStudent+64>`）把参数 `ag` 复制到 `s→age` 字段，它位于距 `s` 的地址偏移 64 字节处。

> - The next section (instructions `<initStudent+56>` thru `<initStudent+64>`) copies the `ag` parameter to the `s→age` field, which is located at an offset of 64 bytes from the address of `s`.

```
0x828 <+56>: ldr  x0, [x29, #40]         // x0 = s
0x82c <+60>: ldr  w1, [x29, #28]         // w1 = ag
0x830 <+64>: str  w1, [x0, #64]          // store ag at (s + 64) (s->age)
```

最后，参数 `g` 的值被复制到 `s→gpa` 字段（字节偏移 72）。注意这里使用了 `s0` 寄存器，因为位置 `x29 + 20` 处存放的数据是单精度浮点数：

> Lastly, the `g` parameter value is copied to the `s→gpa` field (byte offset 72). Notice the use of the `s0` register since the data contained at location `x29 + 20` is single-precision floating point:

```
0x834 <+68>: ldr  x0, [x29, #40]         // x0 = s
0x838 <+72>: ldr  s0, [x29, #20]         // s0 = g
0x83c <+80>: str  s0, [x0, #72]          // store g at (s + 72) (s->gpa)
```

### 9.9.1. 数据对齐与结构体

*9.9.1. Data Alignment and structs*

考虑下面这个修改过的 `studentT` 声明：

> Consider the following modified declaration of `studentT`:

```
struct studentTM {
    char name[63]; //updated to 63 instead of 64
    int  age;
    int  grad_yr;
    float gpa;
};

struct studentTM student2;
```

`name` 字段的大小被改成了 63 字节，而不是原来的 64 字节。想想这会如何影响 `struct` 在内存中的布局。你可能会想当然地把它想象成[图 2](9.9-structs.html) 那样。

> The size of the `name` field is modified to be 63 bytes, instead of the original 64 bytes. Consider how this affects the way the `struct` is laid out in memory. It may be tempting to visualize it as in [Figure 2](9.9-structs.html).

![struct2wrong](/dive-into-systems/C9-ARM64/images/struct2wrong.png)

**图 2.** 更新后的 struct studentTM 的一种错误内存布局。注意结构体的「name」字段从 64 字节减少到了 63 字节。

*Figure 2. An incorrect memory layout for the updated struct studentTM. Note that the "name" field is reduced from 64 to 63 bytes.*

在这种描绘中，`age` 字段出现在紧跟 `name` 字段之后的那个字节。但这是错误的。[图 3](9.9-structs.html) 描绘了实际的内存布局。

> In this depiction, the `age` field occurs in the byte immediately following the `name` field. But this is incorrect. [Figure 3](9.9-structs.html) depicts the actual layout in memory.

![struct2right](/dive-into-systems/C9-ARM64/images/struct2right.png)

**图 3.** 更新后的 struct studentTM 的正确内存布局。字节 a<sub>63</sub> 是编译器为满足内存对齐约束而添加的，它不对应任何字段。

*Figure 3. The correct memory layout for the updated struct studentTM. Byte a<sub>63</sub> is added by the compiler to satisfy memory alignment constraints, but it doesn’t correspond to any of the fields.*

A64 的对齐策略要求：四字节的数据类型（例如 `int`）位于四的倍数的地址上，而 64 位的数据类型（`long`、`double` 和指针数据）位于八的倍数的地址上。对于 `struct`，编译器会在字段之间添加空字节作为「填充」（padding），以确保每个字段都满足其对齐要求。例如，在上面代码片段声明的 `struct` 中，编译器在字节 a<sub>63</sub> 处添加了一个字节的填充，确保 `age` 字段从一个四的倍数的地址开始。在内存中正确对齐的值可以在单次操作中被读取或写入，从而提高效率。

> A64’s alignment policy requires that four-byte data types (e.g., `int`) reside at addresses that are a multiple of four, whereas 64-bit data types (`long`, `double`, and pointer data) reside at addresses that are a multiple of eight. For a `struct`, the compiler adds empty bytes as "padding" between fields to ensure that each field satisfies its alignment requirements. For example, in the `struct` declared in the previous code snippet, the compiler adds a byte of padding at byte a<sub>63</sub> to ensure that the `age` field starts at an address that is at a multiple of four. Values aligned properly in memory can be read or written in a single operation, enabling greater efficiency.

考虑把 `struct` 定义成下面这样时会发生什么：

> Consider what happens when the `struct` is defined as the following:

```
struct studentTM {
    int  age;
    int  grad_yr;
    float gpa;
    char name[63];
};

struct studentTM student3;
```

把 `name` 数组移到最后，就把那个填充字节移到了结构体的末尾，确保 `age`、`grad_yr` 和 `gpa` 都是四字节对齐的。

> Moving the `name` array to the end moves the byte of padding to the end of the struct, ensuring that `age`, `grad_yr`, and `gpa` are four-byte aligned.
